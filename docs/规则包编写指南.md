# 规则包编写指南

规则包 = 一个 YAML 文件，放在 `config/packs/` 下，按文件名顺序自动加载（`--no-packs` 关闭）。
它描述**一个组织**的表单类型清单、表单专项规则参数，以及对通用规则的覆盖。
仓内的 `example-mfg.yaml` 是示例；你的真实规则包属于你自己，不必公开。

## 1. 文件结构

```yaml
meta:
  name: my-org            # 必填，全局唯一；界面与指纹都用它
  version: "1.0"
  description: 某某公司外购件质量记录

forms:                    # 表单类型清单（可省略：则只认内置的供方合格证/检验记录/产品合格证）
  patterns:               # 顺序即优先级；keywords 命中标题区任一即判为该类型
    - {form: 检验证明单, keywords: [检验证明单, 证明单]}
    - {form: 工序流转卡, keywords: [工序流转卡, 流转卡]}
  internal: [检验证明单, 工序流转卡]     # 本单位内部表单（is_internal 口径）
  supplier: [供方合格证, 产品合格证]      # 可省略，缺省沿用内置
  structural:             # 标题被 OCR 漏读时，用表头栏目组合兜底
    - {all: [规定, 实际, 检验员], form: 检验证明单}

overrides:                # 对通用规则（A/B/U 类）的覆盖：只写要改的字段，参数逐项合并
  A12_special_record_empty: {enabled: true}
  B04_blank_cell_no_slash:
    params:
      applies_to: [检验证明单, 工序流转卡]
      field_whitelist: [零件号, 批次号, 规定, 实际, 检验员, 备注]

rules_f:                  # 表单专项规则：判定逻辑在 qaudit/rules_f.py，这里只配参数
  F06_inspection_header_incomplete:
    enabled: true
    level: HIGH
    title: 检验记录首页表头不完整
    clause: 本单位口径：首页表头须填零件号与批次
    params:
      applies_to: [检验记录]
      required_fields: [零件号, 批次]
```

## 2. 规则

- `overrides` 只能指向已存在的规则；写错规则号会直接报错。
- `rules_f` 里的规则号不能与通用层或其他包重复；要改通用规则用 `overrides`。
- `rules_f` 声明了代码里没有实现的规则号会打警告并忽略——先看 `qaudit/rules_f.py` 的 `_REGISTRY` 有哪些。
- 供方证明文件永远优先识别，规则包不能把它改成内部表单。
- `applies_to` / `exclude_forms` 里的表单名必须出现在本包或内置清单里，否则该规则静默不生效。
- `clause` 写依据：国标编号、行业规范或「本单位口径」。**不要复制任何组织内部标准的原文。**
- 改包后跑 `python -m qaudit.cli audit <样本> --out out/x`，看 `[规则库]` 行里包名与启用条数。

## 3. 从零写一个包的顺序

1. 拿 20–30 页本单位的典型记录（脱敏或合成），跑一次 `--no-packs`，看有多少页「未识别」——这就是要补的表单类型
2. 写 `forms.patterns`，重跑，直到未识别 < 5%
3. 看通用层误报最多的规则，用 `overrides` 收窄 `applies_to` 或加白名单
4. 最后才加 `rules_f`：每加一条就用合成样本注入一个违规验证它能抓到
5. 把这批样本判定结果合并进金标准集（`qaudit gold`），作为本包的回归基准
